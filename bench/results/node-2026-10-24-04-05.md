### Findings (SPARQL judgements over the observations)

**Fastest initial render**

- · At 100 items, n3 · function renders from scratch in 28 ms, 5.4× faster than oxigraph · sparql · per-focus (148 ms).
- · At 1000 items, n3 · function renders from scratch in 122 ms, 8.1× faster than oxigraph · sparql · per-focus (985 ms).

**Updates within a 60 fps frame**

- ✓ hybrid · function: every update at 1000 items fits in a frame (worst: add item, 6.81 ms).
- ✓ hybrid · sparql · bulk: every update at 1000 items fits in a frame (worst: add item, 8.71 ms).
- ✓ n3 · function: every update at 1000 items fits in a frame (worst: reorder item, 6.24 ms).
- ! oxigraph · function: 2 of 5 updates at 1000 items miss a 16.7 ms frame (worst: add item, 137.7 ms).
- ! oxigraph · sparql · bulk: 2 of 5 updates at 1000 items miss a 16.7 ms frame (worst: add item, 124.9 ms).
- ! oxigraph · sparql · per-focus: 2 of 5 updates at 1000 items miss a 16.7 ms frame (worst: add item, 115.6 ms).

**Store choice, same SPARQL rules**

- · With identical SPARQL rules at 100 items, mirroring the store into N3.js makes the average update 3.2× faster (1.02 ms vs 3.3 ms on pure Oxigraph): function rules and engine bookkeeping read terms across the WASM boundary on every match.
- · With identical SPARQL rules at 1000 items, mirroring the store into N3.js makes the average update 12× faster (3.58 ms vs 42.93 ms on pure Oxigraph): function rules and engine bookkeeping read terms across the WASM boundary on every match.

**SPARQL vs function rules**

- · On the hybrid store at 100 items, SPARQL rules render from scratch in 77 ms and function rules in 66 ms: functions are 1.2× faster.
- · On the hybrid store at 1000 items, SPARQL rules render from scratch in 365 ms and function rules in 232 ms: functions are 1.6× faster.

**Bulk vs per-focus SPARQL**

- ✓ At 100 items, evaluating each SPARQL rule once for all instances takes 119 ms against 148 ms for one query per instance (1.2×).
- ✓ At 1000 items, evaluating each SPARQL rule once for all instances takes 730 ms against 985 ms for one query per instance (1.4×).
